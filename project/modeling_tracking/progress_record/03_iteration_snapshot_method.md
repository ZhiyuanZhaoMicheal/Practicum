# Iteration Snapshot Reconstruction Method

## Objective
This note documents how `project/modeling/output/iteration_comparison_snapshot.csv` is built, with special focus on Stage B reconstruction and auditability.

## Stage Mapping
- Stage A: Baseline (`no_nlcd`)
- Stage B: Initial NLCD run (reconstructed)
- Stage C: Corrected NLCD run (`with_nlcd`, current)

## Data Sources
- Stage A / Stage C metrics:
  - `project/modeling/output/model_summary_for_report.csv`
- Stage C coverage:
  - `project/modeling/output/nlcd_coverage.csv`
- Stage B metrics (reconstructed):
  - Historical terminal execution record from the first NLCD run before Michael bbox coverage fix.
  - Timeline anchor from `project/modeling_tracking/progress_record/00_bootstrap.md` around `2026-02-23 17:51 UTC`.

## Stage B Reconstructed Values
- OLS `coef_in_buffer`: `0.007481`, p=`0.5982154`
- MixedLM `coef_in_buffer`: `0.007446`, p=`0.5225247`
- Logit `odds_ratio_in_buffer`: `0.965861`, p=`0.7453855`
- Logit `auc`: `0.759041`
- Cox `hazard_ratio_in_buffer`: `1.108306`, p=`1.943801e-05`
- NLCD min coverage: `0.6949286846275753`

## Snapshot Schema
`stage_id,stage_name,model,metric_name,value,p_value,coverage_min,sample_note,source_type,source_ref,is_reconstructed`

## Traceability Rules
- Stage A / Stage C rows use `source_type=current_output` and `is_reconstructed=0`.
- Stage B rows use `source_type=historical_execution_record` and `is_reconstructed=1`.
- Every reconstructed row includes an explicit `source_ref` text pointer.

## Limitations
- Stage B is not regenerated by rerun; it is reconstructed from historical execution records.
- Historical raw artifacts for Stage B were overwritten by later reruns.
- Therefore Stage B supports comparison and diagnosis, but not byte-level rerun reproducibility.

## Reproducibility Recommendation
- If strict reproducibility is required, create a dedicated archived output bundle for each stage before reruns (e.g., `output_snapshots/stage_A|B|C/`).
